## P1 术语卡（只出 6 个，不是 20 个）

```
你在帮我补基础。领域：3D 心脏重建 + 隐式模板 + 稠密点对应。我刚入门。

只给 6 个术语，按"不懂就没法读下一篇论文"排序，从我给的清单里挑最阻塞的：
SDF、marching cubes、template/atlas、warp field、dense correspondence、point identity。

每个术语严格 4 行，总长不超过 120 字：
【一行类比】用日常场景，不许用其他专业词
【在心脏上指什么】具体到 LV 心内膜 / RV / 壁厚
【一句话定义】精确
【我可能误解成】最常见的错误理解

禁止：综述、扩展成段落、举例超过一个、用"本质上""可以说"这类虚词。
禁止一次给超过 6 个。
```

**你的动作（3 分钟）**：关掉窗口，默写其中 3 个的【一句话定义】。写不出的，只让它给这 3 个再换一种说法，不要扩大范围。

## P2 论文拆解工（一次只喂一篇，必须是你最熟的那篇）

```
我完全是门外汉。只给你一篇论文（我贴摘要和 limitation 段）。
严格 6 格，每格 ≤3 行，不许写"综上所述"：

1.【现实问题】临床上到底什么做不了
2.【前人为什么不行】具体到失败机制，不是"性能不足"
3.【核心 trick】一个非技术类比讲清
4.【依赖什么假设】假设破了会怎样
5.【什么时候会坏】越具体越好
6.【实验证明了什么 / 没证明什么】两行分开写

最后一行：这篇属于「输入 / 表达 / 形变与对应 / 输出与评价」哪一层，改的是哪一格。
```

**你的动作（10 分钟）**：合上窗口，白纸写 `input → method → output`，再写一个"它会坏掉的场景"。写完才允许开下一个。

## P3 HTML 演示生成器（一次只做一个，做完再要第二个）

优先级：**A 隐式表面 > B 模板与点身份 > C 稀疏切片**。

```
生成一个单文件 HTML（内联 JS/CSS，不引外部 CDN，双击能开）。
主题：隐式表面与「分辨率 ≠ 细节」。

场景：两个圆的并集，代表双心室横截面（LV 大圆 + RV 小圆），用 SDF 表示。
控件：
- 滑块：等值面 iso（-0.06 ~ 0.06）
- 滑块：采样网格 N（6 ~ 200）
- 开关：加一个半径 3.5% 的小凸起（乳头肌），贴在 LV 内壁
实时显示：
- 用 marching squares 提取的等值线
- 采样点数、轮廓段数、乳头肌轮廓段数
- 一句话判断：乳头肌是否被采到，以及为什么

底部放 3 个问题（不要给答案）：
1. N 从 16 调到 160，形状本身变了吗？变的是什么？
2. 为什么 N=16 时乳头肌会消失？调大 N 能变出输入里没有的细节吗？
3. 这和「网格细分」有什么本质区别？

要求：中文标签；深色背景；滑块拖动要实时；不要超过 400 行。
```

**你的动作（5 分钟）**：**先写下预测**（N=16 时乳头肌会不会出现），再拖。预测错的那条，就是你概念上的洞，写进 `08` 的自检区。

```

给 3 类，每类最多 1 条：
① 缺失的一层或一格
② 我把两个不同概念混进同一格的地方
③ 我描述里最站不住的一句

每条后面加一行："如果真是这样，我会在哪类实验上出错。"
不要说"框架很完整"，不要给鼓励，不要扩展成建议清单。
```

**你的动作**：3 条批注抄到 `08` 旁边，**不改表**。明天被问到就说"这块我知道还缺"。
