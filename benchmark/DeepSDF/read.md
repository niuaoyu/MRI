
## 二、深入解释

### 1. 输入输出（详细到数据维度）

#### 1.1 网络单次前向传播

| 项目 | 维度 | 说明 |
|------|------|------|
| **输入** latent code $\mathbf{z}$ | $(B, 256)$ | $B$ 是 batch 中采样点数；同一个形状的 code 被复制 $B$ 次 |
| **输入** 3D 坐标 $\mathbf{x}$ | $(B, 3)$ | 归一化到单位球内的 3D 空间坐标 |
| **拼接输入** $[\mathbf{z}; \mathbf{x}]$ | $(B, 259)$ | 沿特征维度拼接 |
| **输出** SDF 值 $\hat{s}$ | $(B, 1)$ | 每个点对应的预测 SDF 标量 |

#### 1.2 训练阶段（整个系统）

| 项目 | 维度/大小 | 说明 |
|------|----------|------|
| 训练集 | $N_{shapes} \times 500{,}000$ 个 $(x, s)$ 对 | 如 ShapeNet chair 类约 3000 个形状（Sec. 5, p.7） |
| 每个 batch | $N_{shapes\_per\_batch} \times 16{,}384$ 个点 | 论文默认每个 batch 取若干形状，每形状 16384 个采样点（Sec. 6, p.7） |
| 网络参数 $\theta$ | ~4.8M 参数 | 8 层 MLP，隐层 512 |
| Latent codes $\{\mathbf{z}_i\}$ | $(N_{shapes}, 256)$ | 每个训练形状一个 256 维向量 |
| GT SDF 值 $s$ | $(B, 1)$ | 真实 SDF，已 clamp 到 $[-0.1, 0.1]$ |

#### 1.3 推理阶段

| 项目 | 维度/大小 | 说明 |
|------|----------|------|
| 输入观测点 | $(N_{obs}, 3)$ | 如单张 depth 反投影约 10k-50k 个点 |
| 输入观测 SDF | $(N_{obs}, 1)$ | 表面点 ≈0，自由空间点 >0 |
| 待优化 latent | $(1, 256)$ | 单个新形状的 code |
| 查询网格 | $(256^3, 3) = (16{,}777{,}216, 3)$ | 均匀网格上的所有查询点 |
| 输出 SDF 场 | $(256^3, 1)$ | 每个网格点的 SDF 值 |
| 输出 mesh | $V$ 个顶点 + $F$ 个面 | Marching Cubes 提取，典型 50k-200k 面 |

### 2. 每一步（模块）是怎么处理的（数据流转、维度、大小）

#### 总体数据流转

```
[训练阶段]
原始 Mesh (.obj/.off)
    │  Sec. 5 预处理
    ▼
Watertight Mesh (归一化到单位球)
    │  虚拟相机渲染 + 法向采样
    ▼
SDF 采样点集: {(x_i, s_i)}  每个形状 ~500k 个
    │  DataLoader 随机采样
    ▼
Mini-batch: (B=16384, x∈R³, s∈R¹)  +  对应 z∈R²⁵⁶
    │  拼接
    ▼
[z; x] ∈ R²⁵⁹
    │  8层 MLP
    ▼
ŝ ∈ R¹  (预测 SDF)
    │  Clamped L1 Loss
    ▼
Loss → Adam → 更新 θ 和 {z_i}

[推理阶段]
部分观测 (depth / 点云)
    │  反投影 + 自由空间采样
    ▼
观测 SDF 样本: {(x_j, s_j)}  ~10k-50k 个
    │  冻结 θ, 优化 z
    ▼
ẑ ∈ R²⁵⁶
    │  密集查询
    ▼
SDF 场 on 256³ grid
    │  Marching Cubes
    ▼
完整 Mesh
```

#### 网络内部逐层数据流转

```
输入: [z; x] ∈ (B, 259)
  │
  ├─ Layer 1: Linear(259→512) + WeightNorm + ReLU + Dropout(0.2)
  │   输出: (B, 512)
  │
  ├─ Layer 2: Linear(512→512) + WN + ReLU + Dropout(0.2)
  │   输出: (B, 512)
  │
  ├─ Layer 3: Linear(512→512) + WN + ReLU + Dropout(0.2)
  │   输出: (B, 512)
  │
  ├─ Layer 4: Linear(512→253) + WN + ReLU + Dropout(0.2)
  │   输出: (B, 253)    ← 注意这里故意输出 253 维
  │
  ├─ Skip Connection: concat( (B,253), (B,259) ) = (B, 512)
  │   将 Layer 4 的输出与原始输入 [z;x] 拼接回 512 维
  │
  ├─ Layer 5: Linear(512→512) + WN + ReLU + Dropout(0.2)
  │   输出: (B, 512)
  │
  ├─ Layer 6: Linear(512→512) + WN + ReLU + Dropout(0.2)
  │   输出: (B, 512)
  │
  ├─ Layer 7: Linear(512→512) + WN + ReLU + Dropout(0.2)
  │   输出: (B, 512)
  │
  ├─ Layer 8: Linear(512→512) + WN + ReLU + Dropout(0.2)
  │   输出: (B, 512)
  │
  └─ Layer 9: Linear(512→1) + tanh
      输出: (B, 1)   ← 最终 SDF 预测值
```

#### 训练数据生成流程（Sec. 5, p.7）

```
原始 Mesh (ShapeNet, 非 watertight)
    │  1. 用 Watertight 工具 (如 ManifoldPlus) 修复孔洞
    ▼
Watertight Mesh
    │  2. 归一化: 平移质心到原点, 缩放使最远点到原点距离=1
    ▼
归一化 Mesh (在单位球内)
    │  3. 虚拟相机: ~100 个均匀分布在球面上的视角
    │     渲染 depth map → 反投影得到表面点 P_surf ∈ (N_surf, 3)
    │     同时得到法向 n ∈ (N_surf, 3)
    ▼
表面点 + 法向
    │  4. SDF 采样 (每个形状 ~500k 点):
    │     a) 表面点加高斯噪声 σ₁=0.0025 → 约 250k 点 (近表面)
    │     b) 表面点加高斯噪声 σ₂=0.00025 → 约 250k 点 (极近表面)
    │     c) 均匀采样单位球内点 → 少量 (远表面)
    │     SDF 值 = 到最近表面的距离 × sign(由法向判定)
    ▼
{(x_i ∈ R³, s_i ∈ R¹)}  ~500k 个/形状
    │  5. Clamp: s_i ← clip(s_i, -0.1, 0.1)
    ▼
训练数据 (存储在 .npz 文件中)
```

### 3. 每个模块/步骤的设计原因

#### 3.1 为什么用 SDF 而不是 Occupancy / Voxel / Mesh？

| 问题 | 原因 | 后果 |
|------|------|------|
| Voxel 内存爆炸 | 分辨率翻倍 → 内存 ×8（Sec. 1: "memory scales cubically"） | 实际只能用 64³ 或 128³，表面锯齿严重 |
| Occupancy 只有 0/1 | 丢失了距离信息，表面附近梯度稀疏（Sec. 2: "binary occupancy loses metric information"） | 学习更困难，补全时无法利用"离表面多远"的信息 |
| Mesh 拓扑固定 | 训练前必须确定面数和连接关系（Sec. 1: "mesh-based methods fix topology"） | 无法表示训练集中未出现的拓扑 |
| **SDF 的优势** | 连续、有符号、有距离度量、零等值面天然 watertight | 分辨率只取决于查询密度，不受存储限制 |

#### 3.2 为什么用 Auto-Decoder 而不是 Auto-Encoder？

**问题**：传统 auto-encoder 需要一个 encoder 把输入（点云/voxel）编码成 latent code。

**原因**（Sec. 3.3, p.3-4）：
1. Encoder 的输入模态被固定了（如只能接受点云），但推理时观测可能是 depth、部分 mesh、稀疏 SDF 等任意形式。
2. Encoder 引入了额外的 approximation error：点云 → encoder → code → decoder → SDF，信息在 encoder 中已经丢失。
3. 实验证明 auto-decoder 重建质量更高（Sec. 4.1, p.6: "auto-decoder outperforms auto-encoder in Chamfer distance by 30%"）。

**后果**：
- ✅ 推理时可以处理任意观测形式（统一为 SDF 样本 + 优化）。
- ✅ latent space 更紧凑、更平滑（因为没有 encoder 的 bottleneck 噪声）。
- ❌ 推理变慢（需要 test-time optimization，~800 步）。

#### 3.3 为什么 Latent Code 维度是 256？

**原因**（Sec. 6, p.7）：256 是在表达能力和正则化之间的平衡。太小（如 64）无法编码复杂形状；太大（如 1024）容易过拟合且 latent space 不平滑。论文通过消融实验选择 256。

**后果**：每个形状只需 256 × 4 bytes = 1 KB 存储。

#### 3.4 为什么网络是 8 层 512 宽的 MLP？

**原因**（Sec. 6, p.7）：
- 深度：需要足够深来学习复杂的非线性映射（从 259 维到 1 维的高度非线性函数）。
- 宽度：512 是计算效率和表达能力的折中。
- 论文引用了类似 ResNet 的经验：更深更宽 → 更好的函数逼近。

**后果**：~4.8M 参数，单 GPU 可训练，但推理时 256³ 查询需要约 10 秒。

#### 3.5 为什么在第 4 层做 Skip Connection（输出 253 维 + 拼接回 259 维）？

**问题**：深层 MLP 存在"遗忘"现象——经过多层非线性变换后，网络后半段对原始输入坐标 $\mathbf{x}$ 的敏感度急剧下降（Sec. 3.2, p.3: "deep networks tend to lose high-frequency details of the input"）。

**原因**：将原始输入 $[\mathbf{z}; \mathbf{x}]$ 直接注入到网络中间层，强制后半段网络"记住"精确的坐标信息。

**设计细节**：Layer 4 输出 253 维（而不是 512），这样 253 + 259 = 512，恰好拼回 512 维，不改变后续层的维度。

**后果**：
- ✅ 表面细节显著提升（论文 Fig. 5 对比有/无 skip 的效果）。
- ✅ 高频几何（如椅子扶手、飞机机翼边缘）更清晰。

#### 3.6 为什么用 Weight Normalization 而不是 Batch Normalization？

**原因**（Sec. 6, p.7）：
- SDF 值在不同空间区域差异极大（表面附近 ≈0，远处很大），Batch Norm 的统计量不稳定。
- Weight Normalization 不依赖 batch 统计，对隐式函数回归更稳定。
- 参考了 Salimans & Kingma (2016) 的 Weight Normalization 工作。

**后果**：训练更稳定，收敛更快。

#### 3.7 为什么用 Clamped SDF + tanh？

**问题**：真实 SDF 值在远离表面时可能非常大（如单位球边界处 SDF ≈ 1.0），但我们对远处的精确值并不关心——只有表面附近（SDF ≈ 0）的区域才决定几何形状。

**原因**（Sec. 3.2, p.3）：
$$\text{clamp}(x, \delta) = \min(\delta, \max(-\delta, x)), \quad \delta = 0.1$$
- 截断后，网络只需学习 $[-0.1, 0.1]$ 范围内的精确值。
- 最后一层用 tanh（输出范围 $[-1, 1]$），自然匹配 clamp 后的范围。

**后果**：
- ✅ 学习难度大幅降低（不用拟合大范围数值）。
- ✅ 表面附近精度更高。
- ❌ 远处的 SDF 值不准确（但对表面提取无影响）。

#### 3.8 为什么 Loss 用 L1 而不是 L2？

**原因**（Sec. 3.2, p.3）：L1 对离群值更鲁棒。SDF 采样中不可避免有噪声点（如法向翻转导致 sign 错误），L2 会被这些离群点主导梯度。

**后果**：训练更鲁棒，对数据噪声容忍度更高。

#### 3.9 为什么 Latent Code 有 L2 正则？

**原因**（Sec. 3.3, p.3）：从 MAP 估计的角度，假设先验 $p(\mathbf{z}) = \mathcal{N}(0, \sigma^2 I)$，则：
$$\log p(\mathbf{z}) \propto -\frac{1}{2\sigma^2}\|\mathbf{z}\|^2$$
这自然导出 L2 正则项。$\sigma$ 控制 latent space 的紧凑程度。

**后果**：
- ✅ Latent space 紧凑，code 都在原点附近。
- ✅ 插值有意义（两个合理 code 的中间点也是合理的）。
- ✅ 推理时从 $\mathbf{z}=0$ 初始化有合理的起点。

#### 3.10 为什么推理时用自由空间约束？

**问题**：从单张 depth 图只能看到物体的一面，背面完全未知。如果只用表面点（SDF≈0）优化，网络可能在背面"长出"不合理的结构。

**原因**（Sec. 3.4, p.4）：相机到表面之间的射线上的点一定是自由空间（SDF > 0）。将这些点加入优化，强制网络在已知空旷区域输出正 SDF。

**后果**：
- ✅ 背面补全更合理，不会出现"多出来的腿"等伪影。
- ✅ 论文 Fig. 9 对比：有自由空间约束 vs 无，Chamfer Distance 降低约 40%。

#### 4.3 举例：走一遍数据（训练时一个 batch）

假设训练 ShapeNet Chair 类，当前 batch 包含 1 个形状（index=42），采样 16384 个点。

```
Step 1: 从 DataLoader 取出数据
  - shape_id = 42
  - x = (16384, 3)  ← 16384 个 3D 坐标，如 [0.12, -0.34, 0.56]
  - s = (16384, 1)  ← 对应 GT SDF，如 [0.003, -0.012, 0.087]（已 clamp）

Step 2: 取出 latent code
  - z_42 = (256,)  ← 形状 42 的可学习向量，如 [0.012, -0.034, ...]
  - broadcast: z = (16384, 256)  ← 复制 16384 次

Step 3: 拼接
  - input = [z; x] = (16384, 259)

Step 4: 前向传播
  - Layer 1: (16384, 259) → (16384, 512)
  - Layer 2: (16384, 512) → (16384, 512)
  - Layer 3: (16384, 512) → (16384, 512)
  - Layer 4: (16384, 512) → (16384, 253)
  - Skip:    concat((16384,253), (16384,259)) = (16384, 512)
  - Layer 5-8: (16384, 512) → (16384, 512) × 4
  - Layer 9: (16384, 512) → (16384, 1)
  - ŝ = (16384, 1)，如 [0.005, -0.008, 0.091]

Step 5: 计算 Loss
  - L_sdf = mean(|ŝ - s|) = mean(|[0.005-0.003, -0.008-(-0.012), ...]|) ≈ 0.004
  - L_reg = (1/σ²) * ||z_42||² ≈ 0.001
  - L_total = 0.004 + 0.001 = 0.005

Step 6: 反向传播 + 更新
  - ∂L/∂θ → 更新网络权重 (lr=1e-5)
  - ∂L/∂z_42 → 更新 z_42 (lr=1e-3)
```

### 6. 数据来源解释

#### 6.1 SDF 数据是怎么得到的？（Sec. 5, p.7）

**问题**：神经网络需要大量 $(x, s)$ 监督对，但原始 3D 数据集（如 ShapeNet）只提供 mesh，没有 SDF 值。

**步骤**：
1. **修复 mesh**：ShapeNet 原始 mesh 有孔洞、自交、法向不一致。用 ManifoldPlus 等工具转为 watertight mesh。
   - *为什么*：SDF 的 sign 依赖"内外"的定义，非 watertight mesh 没有明确的内外。
2. **归一化**：平移质心到原点，缩放使最远顶点到原点距离 = 1。
   - *为什么*：所有形状在同一坐标系下，网络不需要学习平移和缩放。
3. **生成表面点**：在 mesh 表面均匀采样 ~100k 个点，计算法向。
4. **计算 SDF**：
   - 对每个采样点 $\mathbf{x}$，找到 mesh 上最近点 $\mathbf{p}$ 和法向 $\mathbf{n}$。
   - 距离 $d = \|\mathbf{x} - \mathbf{p}\|$。
   - 符号：$\text{sign} = \text{sign}((\mathbf{x} - \mathbf{p}) \cdot \mathbf{n})$。正 = 外部，负 = 内部。
   - $s = \text{sign} \times d$。
5. **采样策略**（关键）：
   - 50% 点：表面点 + $\mathcal{N}(0, 0.0025^2)$ 噪声 → 近表面
   - 50% 点：表面点 + $\mathcal{N}(0, 0.00025^2)$ 噪声 → 极近表面
   - 少量：单位球内均匀采样 → 远表面（提供全局结构信息）
6. **Clamp**：$s \leftarrow \text{clip}(s, -0.1, 0.1)$。

#### 6.2 推理时的观测数据是怎么得到的？（Sec. 3.4, p.4）

- **Depth map**：从虚拟相机渲染 GT mesh 得到深度图。
- **反投影**：用相机内参将 depth 转为 3D 点云 → 这些点 SDF ≈ 0。
- **自由空间点**：相机光心到表面点之间的射线上的点 → SDF > 0（取一个小的正值如 0.01）。

## 三、考察问题（费曼方法 / 金字塔方法）

> 以下问题按模块组织，从"是什么"→"为什么"→"如果不这样会怎样"层层递进，适合零基础读者。

---

### 模块 A：SDF 表示

**Q1: 什么是 SDF？用最简单的话解释。**

> **A**: 想象你站在一个房间里。SDF 就是回答"你离最近的墙壁有多远？"的一个数字。如果你站在房间里面，这个数字是**负的**（表示你在物体内部）；如果你站在房间外面，数字是**正的**（表示你在物体外部）；如果你刚好站在墙壁上，数字是 **0**。所以，物体的表面就是所有 SDF=0 的点的集合。
>
> 数学上：$SDF(\mathbf{x}) = \text{signed distance from } \mathbf{x} \text{ to nearest surface}$。
> (Sec. 3.1, p.2: "the SDF of a point is its distance to the closest point on the surface, with sign indicating inside/outside")

**Q2: 为什么 DeepSDF 选择用 SDF 而不是直接输出 mesh（顶点和面）？**

> **A**: 用"盖房子"来类比。Mesh 就像用固定数量的砖块（顶点）搭房子——砖块数量在盖之前就定死了，如果房子形状复杂，砖块不够用就搭不好。SDF 就像用"激光测距仪"——你站在任何位置都能测出离墙多远，不需要预先决定用多少砖块。想要更精细的表面？多测几个点就行，不需要改变"测距仪"本身。
>
> 技术上：Mesh 的拓扑（面数、连接关系）在训练前固定，无法表示训练集中没见过的拓扑（Sec. 1: "mesh-based methods fix topology a priori"）。SDF 是连续函数，零等值面可以有任何拓扑。

**Q3: SDF 的 sign（正负号）是怎么确定的？如果 sign 错了会怎样？**

> **A**: Sign 靠法向确定。表面点 $\mathbf{p}$ 有法向 $\mathbf{n}$（指向外部），查询点 $\mathbf{x}$ 的 sign = $\text{sign}((\mathbf{x}-\mathbf{p}) \cdot \mathbf{n})$。如果点积为正，说明 $\mathbf{x}$ 在法向指向的那一侧（外部），SDF 为正。
>
> 如果 sign 错了（比如法向翻转），网络会学到"内部是外部"，提取的 mesh 会完全反转（像一个空心球变成了实心球的补集）。这就是为什么数据预处理要求 watertight + 法向一致（Sec. 5: "consistent winding order is critical"）。

---

### 模块 B：Auto-Decoder 架构

**Q1: Auto-Decoder 和 Auto-Encoder 有什么区别？用生活例子解释。**

> **A**: 想象你要把一本书的内容压缩成一段摘要，再从摘要还原出书。
> - **Auto-Encoder**：有一个"摘要员"（encoder）读完整本书写出摘要，再有一个"还原员"（decoder）从摘要还原书。问题是摘要员只能读**完整的书**——如果你只给他半本书，他就不会写摘要了。
> - **Auto-Decoder**：没有摘要员。你直接把摘要（latent code）当作一个**可以修改的草稿**，让还原员一边读草稿一边还原书，同时不断修改草稿直到还原出来的书和原书最像。好处是：即使你只有半本书，也可以让还原员从草稿开始猜，慢慢把整本书补全。
>
> 技术上：Auto-encoder 有 encoder $E$ 和 decoder $D$，$\mathbf{z} = E(\text{input})$；Auto-decoder 没有 $E$，$\mathbf{z}$ 是直接优化的参数（Sec. 3.3: "we treat the latent code as a parameter to be optimized"）。

**Q2: 为什么 Auto-Decoder 的重建质量比 Auto-Encoder 好？**

> **A**: 因为 Auto-Encoder 的信息瓶颈更严重。信息流是：原始形状 → encoder（有损压缩）→ code → decoder → 重建。Encoder 本身就会丢失信息（尤其是当输入是稀疏点云时）。Auto-Decoder 的信息流是：code → decoder → 重建，code 是通过**直接最小化重建误差**得到的，没有 encoder 的中间损失。
>
> 论文实验：在 ShapeNet Chair 上，Auto-Decoder 的 Chamfer Distance 比 Auto-Encoder 低约 30%（Sec. 4.1, p.6: "the auto-decoder outperforms the auto-encoder in all metrics"）。

**Q3: Auto-Decoder 的代价是什么？在什么场景下这个代价不可接受？**

> **A**: 代价是**推理速度**。Auto-Encoder 推理只需一次前向传播（~毫秒级）；Auto-Decoder 需要 ~800 步优化（~几十秒）。在需要实时处理的场景（如自动驾驶中的实时 3D 感知、VR/AR 中的实时重建），这个延迟不可接受。后续工作如 DeepSDF++、ConvOccNet 等通过加入 encoder 来加速推理。

---

### 模块 C：网络结构

**Q1: 为什么网络输入是 259 维而不是 3 维？**

> **A**: 如果只输入 3 维坐标 $\mathbf{x}$，网络只能表示**一个**固定形状（因为对于同一个 $\mathbf{x}$，输出总是同一个 SDF 值）。要表示**一整类**形状（如所有椅子），需要告诉网络"你现在要画哪把椅子"。256 维的 latent code $\mathbf{z}$ 就是这个"指令"。256 + 3 = 259 维输入 = "画哪把椅子" + "画哪个位置"。
>
> (Sec. 3.3, p.3: "the network takes as input a latent vector and a 3D position")

**Q2: Skip Connection 为什么在第 4 层而不是第 2 层或第 6 层？**

> **A**: 这是一个经验选择，核心原则是"在网络已经丢失了足够多原始信息、但还有足够多层来利用这些信息的位置注入"。
> - 太早（如第 2 层）：网络还没学到足够的抽象特征，skip 的信息和当前特征高度冗余。
> - 太晚（如第 6 层）：网络已经严重遗忘了坐标信息，注入也来不及恢复细节。
> - 第 4 层（中间位置）：前半段网络已经提取了形状的"全局结构"（由 $\mathbf{z}$ 主导），后半段需要 $\mathbf{x}$ 来添加"局部细节"。
>
> 设计细节：Layer 4 输出 253 维，使得 253 + 259 = 512，恰好匹配后续层的输入维度，不需要额外的投影层（Sec. 3.2, p.3）。

**Q3: 为什么最后一层用 tanh 而不是 ReLU 或线性？**

> **A**: 因为 GT SDF 值已经被 clamp 到 $[-0.1, 0.1]$，tanh 的输出范围是 $[-1, 1]$，自然覆盖这个区间。如果用 ReLU（输出 ≥ 0），网络无法输出负 SDF（物体内部），表面提取会完全失败。如果用线性（无界），网络可能输出很大的值，与 clamp 后的 GT 不匹配，导致梯度不稳定。
>
> (Sec. 3.2: "the final layer uses a tanh activation to bound the output")

### 模块 D：训练过程

**Q1: 训练时网络参数和 latent code 的学习率为什么不同（1e-5 vs 1e-3）？**

> **A**: 用"调收音机"类比。网络参数 $\theta$ 是收音机的**电路设计**——所有频道共享，改动一点就影响所有频道，所以要非常小心（小学习率）。Latent code $\mathbf{z}_i$ 是**调频旋钮**——只影响一个频道（一个形状），可以大胆调（大学习率）。
>
> 技术上：$\theta$ 被所有形状的所有点更新（梯度信息丰富，小步长即可），$\mathbf{z}_i$ 只被形状 $i$ 的点更新（每个 epoch 只看到一次，需要大步长快速收敛）（Sec. 6, p.7: "we use a learning rate of 1e-5 for the network and 1e-3 for the latent codes"）。

**Q2: 为什么 SDF 采样点大部分集中在表面附近？**

> **A**: 用"画地图"类比。如果你要画一个国家的边境线，你会在边境附近密集测量，而不是在国土中心或大洋中间均匀测量——因为边境线才是你关心的。
>
> 技术上：SDF 的零等值面（表面）是我们最终要提取的。远离表面的点 SDF 值很大且变化缓慢，对表面精度贡献小。集中在表面附近采样（$\sigma=0.0025$ 和 $0.00025$）可以让网络把有限的表达能力用在刀刃上（Sec. 5: "we sample more densely near the surface"）。

**Q3: Loss 中的 clamp 操作具体做了什么？如果不 clamp 会怎样？**

> **A**: Clamp 把所有 SDF 值限制在 $[-0.1, 0.1]$ 内。例如：
> - 真实 SDF = 0.5 → clamp 后 = 0.1
> - 真实 SDF = -0.3 → clamp 后 = -0.1
> - 真实 SDF = 0.02 → clamp 后 = 0.02（不变）
>
> 如果不 clamp：一个远离表面的点 SDF=0.8，预测值=0.1，L1 loss=0.7，这个梯度会主导整个 batch 的更新，但我们对这个点的精确距离根本不关心。Clamp 后 loss=0，网络不再浪费容量去拟合远处的精确值（Sec. 3.2: "clamping focuses the network's capacity on the region near the surface"）。

### 模块 E：推理过程

**Q1: 推理时为什么要"优化" latent code？不能直接用网络输出吗？**

> **A**: 因为 Auto-Decoder 没有 encoder，网络不知道"新形状长什么样"。网络只知道"给定一个 code，如何画出对应的形状"。所以面对一个新形状，我们必须先找到一个 code，使得网络用这个 code 画出来的形状和观测数据最匹配。这个"找 code"的过程就是优化。
>
> 类比：你有一个万能画家（网络），他能根据你给的描述（code）画出任何椅子。现在你给他看一张椅子的照片（观测），他需要先想出一个描述（优化 code），使得按这个描述画出来的椅子和照片最像。

**Q2: 自由空间约束具体是什么？为什么它能帮助补全？**

> **A**: 假设你从正面拍了一张椅子的深度照片。照片中能看到椅子的前腿和座面，但看不到后腿。
> - **表面约束**：照片中的点 SDF ≈ 0（这些点在椅子表面上）。
> - **自由空间约束**：从相机到这些表面点之间的空间一定是空的（否则你会看到更近的表面），所以这些空间中的点 SDF > 0。
>
> 如果没有自由空间约束，网络可能在椅子背面"猜"出多余的结构（如第三条前腿），因为这些区域没有表面点约束。加入自由空间约束后，网络被迫在已知空旷区域输出正 SDF，从而抑制伪影（Sec. 3.4, p.4: "free space constraints significantly improve completion quality"; Fig. 9 对比）。

**Q3: Marching Cubes 是什么？为什么需要它？**

> **A**: 网络输出的是一个**函数**（给任何 3D 点返回一个 SDF 值），但我们需要的是一个**mesh**（顶点和三角形面）来做渲染、仿真等下游任务。Marching Cubes 就是把函数变成 mesh 的算法。
>
> 步骤：
> 1. 在空间中铺一个密集网格（如 256×256×256 = 16.7M 个格子点）。
> 2. 在每个格子点上查询 SDF 值。
> 3. 找到 SDF 从正变负（或负变正）的格子边——表面一定穿过这些边。
> 4. 用线性插值确定表面穿过边的精确位置，生成三角形。
>
> 为什么需要：SDF 是隐式表示（数学函数），mesh 是显式表示（几何数据）。下游应用（3D 打印、游戏引擎、医学可视化）几乎都需要显式 mesh。
